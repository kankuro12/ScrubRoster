Ubuntu "Resolute" PPA 404 Fix
If apt update returns 404 Not Found for ppa:ondrej/php/ubuntu resolute, map the repository codename to noble (24.04 LTS) using the commands below:
Bash Command — Fix PPA 404 & Install PHP 8.4
# Fix Ondřej PPA 404 for Ubuntu Resolute by mapping to Noble (24.04 LTS)
sudo add-apt-repository ppa:ondrej/php -y
sudo sed -i 's/resolute/noble/g' /etc/apt/sources.list.d/ondrej-ubuntu-php*.sources 2>/dev/null || true
sudo sed -i 's/resolute/noble/g' /etc/apt/sources.list.d/ondrej-ubuntu-php*.list 2>/dev/null || true

Configure .env File for MariaDB (High-Performance Unix Socket Connection)

Performance Optimization
Using Unix Domain Socket connection (DB_SOCKET=/var/run/mysqld/mysqld.sock) is 15-25% faster than TCP loopback, reducing query latency by eliminating TCP network stack overhead.
.env Configuration (MariaDB Unix Socket Engine)
APP_NAME="CleanWay Backend"
APP_ENV=production
APP_DEBUG=false
APP_URL=https://cleanway.needtechnosoft.com

DB_CONNECTION=mariadb
DB_SOCKET=/var/run/mysqld/mysqld.sock
DB_DATABASE=cleanway_db
DB_USERNAME=cleanway_user
DB_PASSWORD="StrongSecretPassword123!"

SESSION_DRIVER=redis
CACHE_STORE=redis
QUEUE_CONNECTION=redis

REDIS_CLIENT=phpredis
REDIS_HOST=127.0.0.1
REDIS_PORT=6379

server {
    listen 80;

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;

    root /var/www/cleanway_backend/public;

    # Cloudflare Origin CA Certificate (Valid up to 15 years)

        fastcgi_pass unix:/var/run/php/php8.4-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
        fastcgi_hide_header X-Powered-By;
    }

    location ~ /\. {
        deny all;
    }
}

C. Cloudflare Origin CA Certificate Installation

Since Cloudflare proxy handles public TLS termination, install a 15-year Cloudflare Origin CA Certificate on your server:

Cloudflare Origin CA Certificate Setup
# 1. Create SSL Certificate in Cloudflare Dashboard -> SSL/TLS -> Origin Server -> Create Certificate (Validity: 15 Years)
# 2. Paste Origin Certificate into /etc/ssl/certs/cleanway-origin.pem
# 3. Paste Private Key into /etc/ssl/private/cleanway-origin.key

sudo chmod 644 /etc/ssl/certs/cleanway-origin.pem
sudo chmod 600 /etc/ssl/private/cleanway-origin.key
sudo chown root:root /etc/ssl/certs/cleanway-origin.pem /etc/ssl/private/cleanway-origin.key

# 4. Set Cloudflare SSL/TLS Encryption Mode to "Full (strict)"
sudo nginx -t && sudo systemctl reload nginx

7. Fail2Ban Security Configuration

Brute-Force Protection for SSH, Nginx Auth, and Rate-Limiting

Fail2Ban monitors log files and bans malicious IPs attempting brute-force attacks or scanners.

A. Configure Local Jail Settings

Create configuration file /etc/fail2ban/jail.local:

Fail2Ban Config — /etc/fail2ban/jail.local
[DEFAULT]
bantime  = 1h
findtime = 10m
maxretry = 5
banaction = iptables-multiport

[sshd]
enabled = true
port    = ssh
logpath = %(sshd_log)s
backend = %(sshd_backend)s

[nginx-http-auth]
enabled  = true
filter   = nginx-http-auth
port     = http,https
logpath  = /var/log/nginx/error.log

[nginx-botsearch]
enabled  = true
filter   = nginx-botsearch
port     = http,https
logpath  = /var/log/nginx/access.log
maxretry = 2

[nginx-req-limit]
enabled  = true
filter   = nginx-limit-req
port     = http,https
logpath  = /var/log/nginx/error.log
maxretry = 10

B. Create Custom Filter for Laravel Login Brute Force

Create filter /etc/fail2ban/filter.d/laravel-login.conf:

Fail2Ban Filter — /etc/fail2ban/filter.d/laravel-login.conf
[Definition]
failregex = ^<HOST> .* "POST /login HTTP/.*" (401|422|429)
ignoreregex =

Add the Laravel jail to /etc/fail2ban/jail.local:

Jail Snippet
[laravel-login]
enabled  = true
filter   = laravel-login
port     = http,https
logpath  = /var/log/nginx/access.log
maxretry = 5
findtime = 5m
bantime  = 2h

C. Enable & Verify Fail2Ban Service

Bash Command — Restart & Check Status
sudo systemctl enable --now fail2ban
sudo systemctl restart fail2ban

# Check active jails
sudo fail2ban-client status

# Inspect specific jail (e.g. sshd or laravel-login)
sudo fail2ban-client status sshd

8. Supervisor Queue Worker Service

Asynchronous Job Processing Configuration

Create configuration file /etc/supervisor/conf.d/cleanway-worker.conf:

Supervisor Config — /etc/supervisor/conf.d/cleanway-worker.conf
[program:cleanway-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/cleanway_backend/artisan queue:work redis --sleep=3 --tries=3 --max-time=3600
autostart=true
autorestart=true
stopasgroup=true
killasgroup=true
user=www-data
numprocs=2
redirect_stderr=true
stdout_logfile=/var/www/cleanway_backend/storage/logs/worker.log
stopwaitsecs=3600
Bash Command — Start Supervisor Worker
sudo supervisorctl reread
sudo supervisorctl update
sudo supervisorctl start cleanway-worker:*
sudo supervisorctl status
